## このステップのゴール

縦か横に同じ宝石が3つ以上並んだ「そろい」を見つける関数 `findRuns()` を作ります。入れかえてもそろわなかったときは元に戻し、そろったときだけ残り手数（MOVES）を1つ減らします。さらに「動かせる手が1つもない盤面」が最初に出ないようにします。

## そろいを見つける

`newBoard()` 関数の **後ろ**（`swapCells` の上）に追加します。

```js:game.js
  function findRuns() {
    const runs = [];
    for (let r = 0; r < N; r++) {
      let c = 0;
      while (c < N) {
        const t = grid[r][c].t;
        let e = c + 1;
        while (e < N && t < COLORS && grid[r][e].t === t) e++;
        if (t < COLORS && e - c >= 3) runs.push({ dir: 'h', t, cells: range(c, e).map((x) => [r, x]) });
        c = e;
      }
    }
    for (let c = 0; c < N; c++) {
      let r = 0;
      while (r < N) {
        const t = grid[r][c].t;
        let e = r + 1;
        while (e < N && t < COLORS && grid[e][c].t === t) e++;
        if (t < COLORS && e - r >= 3) runs.push({ dir: 'v', t, cells: range(r, e).map((y) => [y, c]) });
        r = e;
      }
    }
    return runs;
  }
  function range(a, b) { const o = []; for (let i = a; i < b; i++) o.push(i); return o; }
```

### 「同じ色の連続」を数える

前半は横方向です。各行について左から見ていき、

1. 位置 `c` の色を `t` とする
2. `e` を右へ1つずつ進め、同じ色が続くあいだ数える
3. 続いた長さ `e - c` が 3 以上なら「そろい（run）」として記録する
4. `c = e` として、続きが途切れた場所から次を調べる

という流れです。後半は同じことを縦方向にやっています。1行を左から右へ1回なめるだけなので、とても速く調べられます。

記録する run は `{ dir: 'h' か 'v', t: 色, cells: [[行, 列], ...] }` という形です。`range(a, b)` は `a` から `b - 1` までの数の配列を作る小さな関数で、`range(2, 5).map((x) => [r, x])` なら `[[r, 2], [r, 3], [r, 4]]` になります。向き `dir` と長さはステップ7の特殊ジェムづくりで使います。

`t < COLORS` という条件は、ステップ7で登場する **カラーボム**（種類番号 `COLORS` ＝ 6）を「色」として数えないためのものです。今は気にしなくて大丈夫です。

## 動かせる手があるか調べる

`swapCells()` 関数の **後ろ** に追加します。

```js:game.js
  function hasMove() {
    for (let r = 0; r < N; r++) {
      for (let c = 0; c < N; c++) {
        for (const [dr, dc] of [[0, 1], [1, 0]]) {
          const r2 = r + dr, c2 = c + dc;
          if (!inside(r2, c2)) continue;
          swapCells([r, c], [r2, c2]);
          const ok = findRuns().length > 0;
          swapCells([r, c], [r2, c2]);
          if (ok) return true;
        }
      }
    }
    return false;
  }
```

すべてのマスについて「右どなり」と「下どなり」と **実際に入れかえてみて**、そろいができるか `findRuns()` で調べ、すぐに元に戻します。左や上と入れかえるパターンは、そのマスから見た右・下として必ずどこかで調べられるので、2方向だけで十分です。1つでも見つかれば `true` です。

このように「試しにやってみて、結果を見たら戻す」という方法は、ルールが少しややこしくても確実に判定できる便利な考え方です。

## 手のない盤面を作らない

`newBoard()` 関数全体を `do { ... } while (!hasMove());` で包みます。

```js:game.js
  function newBoard() {
    do {
      grid = [];
      for (let r = 0; r < N; r++) {
        grid.push([]);
        for (let c = 0; c < N; c++) {
          let t;
          do { t = rnd(COLORS); } while (
            (c >= 2 && grid[r][c - 1].t === t && grid[r][c - 2].t === t) ||
            (r >= 2 && grid[r - 1][c].t === t && grid[r - 2][c].t === t)
          );
          grid[r].push(gem(t));
        }
      }
    } while (!hasMove());
  }
```

できあがった盤面に動かせる手がなければ、もう一度作り直します。

## そろわなければ元に戻す

`afterSwap()` 関数を次のように書きかえます。

```js:game.js
  function afterSwap(a, b) {
    swapCells(a, b);
    const runs = findRuns();
    if (!runs.length) {
      state = 'unswap';
      anim = { t: 0, dur: 160, a, b };
      swapCells(a, b);
      return;
    }
    moves--; movesEl.textContent = moves;
    state = 'idle';
  }
```

入れかえたあとに `findRuns()` でそろいを探し、1つもなければ `'unswap'` 状態にしてデータを元に戻します。前のステップで `draw()` に入れた `p = 1 - p` のおかげで、見た目は「入れかえた位置から元の位置へ戻る」逆再生になります。

そろったときだけ `moves` を1つ減らし、ヘッダーの表示も更新します。

## スタートで手数を戻す

`start()` 関数を次のように書きかえます。

```js:game.js
  function start() {
    newBoard();
    moves = MAX_MOVES; selected = null;
    movesEl.textContent = moves;
    overlay.classList.add('hidden');
    state = 'idle';
  }
```

> [!CHECK] 動作チェック
> - 入れかえても3つそろわないときは、宝石がいったん入れかわってから元の位置に戻ってくる。MOVES は減らない
