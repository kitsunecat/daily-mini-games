## このステップのゴール

3つのファイルを用意して、画面の土台を作ります。上に「TIME・陣地・BEST」の表示、まん中にゲームを描く **Canvas**（キャンバス）、その上に重ねるタイトル画面（オーバーレイ）を置き、Canvas に方眼紙のようなマス目を描くところまで進めます。

完成すると、こんなゲームになります。

- 40 × 40 マスのフィールドに、自分（青）と3人の敵（あか・みどり・オレンジ）がいて、それぞれ小さな陣地を持っている
- キャラは一定のリズムで1マスずつ進み続ける。スワイプや矢印キーで向きを変える
- 自分の陣地の外に出ると、通ったマスに **線** が残る。陣地に戻ると、線でぐるっと囲んだ場所がまるごと自分の陣地になる
- 引いている途中の線は弱点。自分の線にぶつかったり、敵に線を横切られたりするとアウト。逆に敵の線を横切れば、その敵を倒せる
- 90 秒でどれだけ陣地を広げられるか（何 % 取れるか）を競う

まずは HTML です。このステップで画面の部品はすべてそろえてしまい、以降は `game.js` だけを育てていきます。

- `<canvas id="cv">` が、ゲームを描く画用紙です。`width` / `height` はあとで JavaScript から画面に合わせて設定しなおします。
- 上の `#time`（残り時間）、`#score`（自分の陣地の割合）、`#best`（ハイスコア）は、ステップ4・5・8で JavaScript から書きかえます。
- `#toast` は「あかをたおした！」などを一瞬だけ表示するメッセージ、`#overlay` はタイトル画面とゲームオーバー画面をかねるパネルです。
- `<script>` は `</body>` の直前に置きます。HTML の要素が全部できたあとで JavaScript が動くので、`getElementById` で確実に要素を取れます。

## game.js

最後に JavaScript です。まずは「Canvas を画面に合わせて用意し、毎フレーム描き直す」いちばん小さな形を作ります。

```js:game.js
(() => {
  'use strict';
  const N = 40;                 // grid size (N x N)
  const cv = document.getElementById('cv');
  const ctx = cv.getContext('2d');
  const $ = (id) => document.getElementById(id);
  const overlay = $('overlay'), btnStart = $('start');

  let state = 'title', lastT = 0;

  // ---------- canvas sizing ----------
  let S = 360, C = S / N;
  function resize() {
    const dpr = Math.min(window.devicePixelRatio || 1, 2);
    const r = cv.getBoundingClientRect();
    const px = Math.max(200, Math.round(Math.min(r.width, r.height || r.width)));
    cv.width = cv.height = Math.round(px * dpr);
    ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
    S = px; C = S / N;
  }
  window.addEventListener('resize', () => { resize(); draw(); });

  // ---------- game flow ----------
  function start() {
    resize();
    state = 'play';
    overlay.classList.add('hide');
    lastT = performance.now();
  }

  // ---------- loop ----------
  function draw() {
    ctx.fillStyle = '#f4f1ea';
    ctx.fillRect(0, 0, S, S);
    ctx.strokeStyle = 'rgba(0,0,0,.05)';
    ctx.lineWidth = 1;
    ctx.beginPath();
    for (let k = 1; k < N; k++) {
      ctx.moveTo(k * C, 0); ctx.lineTo(k * C, S);
      ctx.moveTo(0, k * C); ctx.lineTo(S, k * C);
    }
    ctx.stroke();
  }

  function frame(t) {
    const dt = Math.min(0.05, (t - lastT) / 1000);
    lastT = t;
    draw();
    requestAnimationFrame(frame);
  }

  // ---------- input ----------
  btnStart.addEventListener('click', start);
  overlay.addEventListener('click', (ev) => { if (ev.target === overlay) start(); });
  document.addEventListener('touchmove', (ev) => ev.preventDefault(), { passive: false });

  resize();
  requestAnimationFrame((t) => { lastT = t; frame(t); });
})();
```

### 全体を `(() => { ... })();` で包む

ファイル全体をアロー関数で包んで、その場で呼び出しています（即時実行関数）。こうすると中で作った変数がページ全体に漏れず、ほかのスクリプトと名前がぶつかりません。`'use strict';` は、うっかりミス（宣言していない変数への代入など）をエラーとして教えてくれるモードです。

### N と C … マス目の大きさ

このゲームのフィールドは `N = 40`、つまり 40 × 40 マスです。`S` は Canvas の一辺の長さ（CSS ピクセル）、`C = S / N` は **1マスの大きさ** です。以降、マス `(x, y)` を描くときは「左上が `(x * C, y * C)`、大きさ `C`」と計算します。

### resize() … くっきり表示するための工夫

Canvas は「中身のピクセル数（`cv.width` / `cv.height`）」と「画面に表示される大きさ（CSS）」が別々です。スマホのような高精細な画面（`devicePixelRatio` が 2 や 3）で中身のピクセルが少ないと、引きのばされてぼやけてしまいます。

そこで `resize()` では次のことをしています。

1. `getBoundingClientRect()` で、Canvas が実際に画面に表示されている大きさを調べる
2. その大きさ × `dpr` を中身のピクセル数にする（`dpr` は大きすぎると重くなるので最大 2）
3. `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)` で「以降の描画を `dpr` 倍に拡大する」設定にする

こうすると、描くときは CSS ピクセルの座標（`S` × `S`）で考えるだけで、画面にはくっきり表示されます。ウィンドウの大きさが変わったら（`resize` イベント）、もう一度計算して描き直します。

### state … いまどの場面か

`state` は、ゲームがいまどの場面にいるかを表す文字列です。`'title'`（タイトル画面）、`'play'`（プレイ中）、`'over'`（ゲームオーバー、ステップ5）の3つを使います。「場面ごとにできることを変える」のは、ゲームづくりでよく使う考え方です（**状態遷移**）。

### frame() と dt … ゲームループ

`requestAnimationFrame(frame)` は「次に画面を描きかえるタイミングで `frame` を呼んで」とブラウザに頼む命令です。`frame` の最後でまた自分を予約するので、1秒に約60回 `draw()` がくり返されます。これが **ゲームループ** です。

`frame` には、そのときの時刻（ミリ秒）が `t` として渡されます。前回との差を秒に直したものが `dt`（デルタタイム）です。ステップ3で「キャラを一定間隔で進める」ときに使います。タブを切りかえて戻ったときに `dt` が大きくなりすぎないよう、`Math.min(0.05, …)` で上限をつけています。

### draw() … 方眼紙を描く

`fillRect` で全体をクリーム色にぬってから、縦横の線を `N - 1` 本ずつ引いています。`beginPath()` → `moveTo` / `lineTo` を何度も → 最後に1回だけ `stroke()`、とまとめて描くと速く描けます。

### スタート

ボタンを押すか、オーバーレイの背景をタップしたら `start()` でオーバーレイを隠し、`state` を `'play'` にします。最後の `touchmove` の `preventDefault()` は、iPhone などでスワイプしたときに画面全体がゆれるのを防ぐためのものです（`passive: false` をつけないと止められません）。

> [!CHECK] 動作チェック
> - タイトル画面に「じんとりライン」と遊び方が表示される
> - 「タップでスタート」を押すとタイトル画面が消え、クリーム色の正方形にうっすらとマス目が見える
> - 画面の幅を変えても、正方形のまま収まり、マス目がぼやけない
> - 上の TIME・陣地・BEST はまだ動かなくてOK
