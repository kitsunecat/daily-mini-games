## このステップのゴール

このゲームの主役、**数字ゲート** を作ります。道に左右2つ並んだゲートが次々に流れてきて、くぐった側の計算（＋・×・－・÷）で人数が変わります。ふえたら「ピロッ」、へったら「ブー」と画面がゆれる効果音つき。人数が 0 になったらゲームオーバーにします。

ここで、このゲームでいちばん大事な **「道の上の位置」と「画面の y」** の考え方が出てきます。

## 効果音の関数

`resize()` のあとの `window.addEventListener('resize', ...)` の行の **下**（`// ---------- state ----------` の上）に追加します。

```js:game.js
  // ---------- audio ----------
  let actx = null;
  function beep(freq, dur, type, vol) {
    try {
      if (!actx) actx = new (window.AudioContext || window.webkitAudioContext)();
      const o = actx.createOscillator(), g = actx.createGain();
      o.type = type || 'square';
      o.frequency.value = freq;
      g.gain.setValueAtTime(vol || 0.06, actx.currentTime);
      g.gain.exponentialRampToValueAtTime(0.0001, actx.currentTime + dur);
      o.connect(g); g.connect(actx.destination);
      o.start(); o.stop(actx.currentTime + dur);
    } catch (e) { /* ignore */ }
  }
```

**Web Audio API** を使って、音のファイルなしで「ピッ」という音を作ります。

- `AudioContext` は音を作る工場のようなものです。ブラウザは「ユーザーが操作するまで音を出さない」決まりなので、最初に鳴らすとき（スタートを押したとき）に作ります
- `createOscillator()` は一定の高さの音を出し続ける発振器、`createGain()` は音量のつまみです。`freq` が音の高さ（Hz）、`type` が音色（`'sine'`・`'square'`・`'triangle'`・`'sawtooth'`）です
- 音量を `exponentialRampToValueAtTime()` で `dur` 秒かけてほぼ 0 まで下げると、「プツッ」と切れずに自然に消えます
- 全体を `try { ... } catch` で囲み、音が使えない環境でもゲームが止まらないようにしています

## 変数と小さな便利関数

`let n, px, targetX, dist, speed, t;` の行を **書きかえ**、その **下** に2つの関数を追加します。

```js:game.js
  let n, px, targetX, dist, speed, objs, nextAt, stage, shake, t;

  const rand = (a, b) => a + Math.random() * (b - a);
  const randi = (a, b) => Math.floor(rand(a, b + 1));
```

- `objs` … 道の上にある物（ゲートや、あとで出てくる敵など）をまとめて入れる配列です
- `nextAt` … 次の物を置く **道の上の位置**
- `stage` … 今のステージ番号。数字ゲートの数の大きさに使います
- `shake` … 画面をゆらす残り時間（秒）
- `rand(a, b)` は a 以上 b 未満のランダムな小数、`randi(a, b)` は a 以上 b **以下** のランダムな整数を返します

`reset()` も **書きかえ** ます。

```js:game.js
  function reset() {
    n = 1; px = MID; targetX = MID; dist = 0; speed = 150; objs = []; nextAt = 260;
    stage = 1; shake = 0; t = 0;
  }
```

## ゲートを作る

`reset()` 関数の **下**（`// ---------- update ----------` の上）に追加します。

```js:game.js
  // ---------- level generation ----------
  function goodOp() {
    const r = Math.random();
    if (r < 0.18) return { op: 'x', v: Math.random() < 0.8 ? 2 : 3 };
    return { op: '+', v: randi(4, 10) + stage * randi(2, 5) };
  }
  function badOp() {
    const r = Math.random();
    if (r < 0.25 && n > 8) return { op: '÷', v: 2 };
    return { op: '-', v: randi(3, 8) + stage * randi(2, 4) };
  }

  function spawn(kind, d) {
    if (kind === 'gate') {
      let a, b;
      if (Math.random() < 0.4) { a = goodOp(); b = goodOp(); } else { a = goodOp(); b = badOp(); }
      if (Math.random() < 0.5) [a, b] = [b, a];
      objs.push({ kind, d, left: a, right: b, used: false });
      return 150;
    }
    return 150;
  }

  function ensureSpawns() {
    while (nextAt < dist + H) {
      nextAt += spawn('gate', nextAt);
    }
  }
```

### ゲートの計算は `{ op, v }` で表す

1つのゲートの計算を `{ op: '+', v: 7 }`（＋7）のようなオブジェクトで表します。

- `goodOp()` は仲間がふえる計算です。18% の確率で ×2（たまに ×3）、それ以外は ＋ です。＋の数は `stage` が上がるほど大きくなります
- `badOp()` は仲間がへる計算です。人数が 8 人より多いときだけ、25% の確率で ÷2、それ以外は － です
- ゲートは「良い・良い」が 40%、「良い・悪い」が 60% です。`[a, b] = [b, a]` は **分割代入** を使った入れかえの書き方で、半分の確率で左右を入れかえて、どちらが良いか分からないようにします

### 道の上の位置 d

ゲートには `d`（distance）という **道の上の位置** を持たせます。「スタートから d だけ進んだ地点に置いてある」という意味です。

`spawn()` は物を1つ置いて、**次の物までの間隔**（ゲートなら 150）を返します。`ensureSpawns()` は、`nextAt` が「今の距離 `dist` ＋ 画面の高さ `H`」より手前のあいだ、物を置き続けます。つまり **これから画面に入ってくる少し先までだけ** 物を作るので、どこまで進んでも物が切れず、作りすぎることもありません。

## update() でゲートをくぐる

`update()` を **書きかえ** ます。`px += ...` の下に `ensureSpawns();` からの処理を足し、`if` ブロックの外に `shake` を減らす1行を足しています。

```js:game.js
  function update(dt) {
    t += dt;
    if (state === 'play') {
      speed = Math.min(300, 150 + dist / 60);
      dist += speed * dt;
      const keyV = (keys.left ? -1 : 0) + (keys.right ? 1 : 0);
      if (keyV) targetX += keyV * 280 * dt;
      const r = crowdRadius(n);
      targetX = Math.max(ROAD_L + r, Math.min(ROAD_R - r, targetX));
      px += (targetX - px) * Math.min(1, dt * 14);
      ensureSpawns();

      for (const o of objs) {
        const y = CROWD_Y - (o.d - dist);
        if (o.kind === 'gate') {
          if (!o.used && y >= CROWD_Y) {
            o.used = true;
            const g = px < MID ? o.left : o.right;
            o.chosen = px < MID ? 'L' : 'R';
            const before = n;
            if (g.op === '+') n += g.v;
            else if (g.op === 'x') n *= g.v;
            else if (g.op === '-') n -= g.v;
            else if (g.op === '÷') n = Math.floor(n / g.v);
            n = Math.min(n, 99999);
            if (n > before) { beep(660, 0.1, 'square', 0.05); setTimeout(() => beep(880, 0.1, 'square', 0.05), 70); }
            else { beep(220, 0.18, 'triangle', 0.08); shake = 0.15; }
            if (n <= 0) { n = 0; gameOver(); return; }
          }
        }
      }
      objs = objs.filter(o => CROWD_Y - (o.d - dist) < H + 120);
    }
    if (shake > 0) shake -= dt;
    countEl.textContent = n;
  }
```

### 画面の y は「まだ何だけ先にあるか」で決まる

`const y = CROWD_Y - (o.d - dist);` がこのゲームのスクロールのすべてです。

- `o.d - dist` は「その物が、群れから **あとどれだけ先** にあるか」です
- 群れは画面の `CROWD_Y` にいるので、そこから先にあるぶんだけ **上** に描けば（y は上ほど小さい）、遠くの物ほど画面の上に見えます
- `dist` が増えると `o.d - dist` が小さくなり、物はだんだん下へ降りてきます。群れの位置で `o.d - dist` が 0 になり、`y` がちょうど `CROWD_Y` になります

### くぐった瞬間に1回だけ計算する

`y >= CROWD_Y`（ゲートが群れの高さまで来た）になった最初のフレームで計算します。`o.used = true` にして、同じゲートで2回計算しないようにするのがポイントです。

- 群れのまん中 `px` が `MID` より左なら左のゲート、右なら右のゲートです。どちらを選んだかは `o.chosen` に覚えて、あとで描くときに使います
- ÷ は `Math.floor` で小数を切り捨て、人数は最大 99999 までにします
- ふえたら高い音を2つ（`setTimeout` で 0.07 秒ずらす）、へったら低い音を鳴らして `shake` で画面をゆらします
- 0 人以下になったら `gameOver()` を呼んで、`return` でこのフレームの処理を終えます

最後の `objs.filter(...)` は、画面の下へ通りすぎた物を配列から取りのぞきます。残しておくと配列がどんどん長くなり、だんだん重くなってしまうからです。

## ゲートを描く

`label()` 関数の **下**（`function draw()` の上）に、2つの小さな関数を追加します。

```js:game.js
  function opText(g) { return (g.op === 'x' ? '×' : g.op) + g.v; }
  function opGood(g) { return g.op === '+' || g.op === 'x'; }
```

`opText()` はゲートに書く文字（`'×2'` や `'+7'`）を、`opGood()` は仲間がふえる計算かどうかを返します。

次に `draw()` の中、`ctx.save();` の **すぐ下** に画面をゆらす1行を追加します。

```js:game.js
    ctx.save();
    if (shake > 0) ctx.translate(rand(-3, 3), rand(-3, 3));
```

`ctx.translate(x, y)` は、このあと描くものすべてを (x, y) だけずらす命令です。毎フレームちがう方向へ少しずつずらすと、画面がガタガタゆれます。最後の `ctx.restore()` で元にもどるので、ゆれが積み重なることはありません。

さらに、白い線を描く `for` 文の **下**（`// player crowd` の上）に追加します。

```js:game.js
    if (objs) for (const o of objs) {
      const y = CROWD_Y - (o.d - dist);
      if (y < -80 || y > H + 80) continue;
      if (o.kind === 'gate') {
        const sides = [[ROAD_L, MID, o.left, 'L'], [MID, ROAD_R, o.right, 'R']];
        for (const [a, b, g, s] of sides) {
          const good = opGood(g);
          const dim = o.used && o.chosen !== s;
          ctx.globalAlpha = o.used ? (dim ? 0.25 : 0.55) : 0.85;
          ctx.fillStyle = good ? '#3fb0ff' : '#ff5a6a';
          ctx.fillRect(a + 4, y - 22, b - a - 8, 34);
          ctx.globalAlpha = 1;
          ctx.fillStyle = good ? '#1d6fb8' : '#b5303e';
          ctx.fillRect(a + 2, y - 30, 8, 46); ctx.fillRect(b - 10, y - 30, 8, 46);
          if (!dim) label(opText(g), (a + b) / 2, y - 5, 26, '#fff');
        }
      }
    }
```

- 物ごとに、update と同じ式で画面の `y` を求めます。画面の外（上下 80 より外）の物は `continue` で描くのを飛ばします
- `sides` は「左端・右端・計算・どちら側か」を左右ぶん並べた配列です。`for (const [a, b, g, s] of sides)` のように **分割代入** で受け取ると、同じ処理で左右を描けます
- 良いゲートは青、悪いゲートは赤。半透明（`globalAlpha`）の板と、両はしの濃い柱で描きます
- くぐったあとは、選んだ側を少しうすく、選ばなかった側をもっとうすくして数字も消します。「どちらを選んだか」が目で分かります
- 描く物が群れより先なので、ゲートは群れの **うしろ** に描かれます

## ゲームオーバー

`start()` の最後に効果音を1行足し、その **下** に `gameOver()` を追加します。

```js:game.js
  function start() {
    reset();
    state = 'play';
    overlay.classList.add('hidden');
    beep(440, 0.08);
  }
  function gameOver() {
    if (state !== 'play') return;
    state = 'over';
    n = 0;
    beep(150, 0.4, 'triangle', 0.1);
    setTimeout(() => {
      ovTitle.textContent = 'ゲームオーバー';
      ovText.innerHTML = '仲間がいなくなってしまった…<br>もう一度挑戦しよう！';
      startBtn.textContent = 'もう一度';
      overlay.classList.remove('hidden');
    }, 700);
  }
```

- 最初の `if (state !== 'play') return;` で、何回呼ばれてもゲームオーバーの処理は1回だけにします
- `setTimeout(..., 700)` で 0.7 秒待ってからオーバーレイを出すと、「何が起きたか」を見てから結果画面に移れます
- ボタンの文字を「もう一度」に変えます。押すと `start()` → `reset()` で全部が最初の値にもどるので、そのままリトライになります

> [!CHECK] 動作チェック
> - スタートすると、上から左右2つ並んだゲートが次々に流れてくる。青は「+7」「×2」など、赤は「-5」など
> - 左右に動いて青いゲートをくぐると「ピロッ」と鳴って人数がふえ、群れが大きくなる。×2 をくぐると人数が2倍になる
> - 赤いゲートをくぐると低い音がして画面がゆれ、人数がへる
> - くぐったゲートは、選んだ側がうすく残り、選ばなかった側はもっとうすくなる
> - 1人のときに赤いゲートをくぐると 0 人になり、少しして「ゲームオーバー」が出る。「もう一度」で最初からやり直せる
