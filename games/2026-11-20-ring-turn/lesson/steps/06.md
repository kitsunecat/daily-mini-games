## このステップのゴール

ゲームのルールの中心、「**内・中・外の3つの玉の色が同じ方向にそろったら消える**」を作ります。消えた場所には新しい玉が入り、その玉でまたそろえば **連鎖** になります。消すとスコアが入り、手数も回復します。

## findMatches() … そろった区画を探す

`function newBoard() { ... }` 全体を、次のコードに **書きかえます**（`newBoard()` の後半と、新しい関数 `findMatches()` が増えています）。

```js:game.js
  function newBoard() {
    grid = [];
    for (let i = 0; i < RINGS; i++) {
      grid.push([]);
      for (let k = 0; k < N; k++) grid[i].push(rnd());
    }
    // remove initial matches
    for (let guard = 0; guard < 100; guard++) {
      const m = findMatches();
      if (!m.length) break;
      m.forEach(k => { grid[1][k] = rnd(); });
    }
  }

  function findMatches() {
    const out = [];
    for (let k = 0; k < N; k++) {
      const c = grid[0][k];
      if (c >= 0 && grid[1][k] === c && grid[2][k] === c) out.push(k);
    }
    return out;
  }
```

### そろっているかの判定

区画 `k` について、内側の玉の色 `grid[0][k]` と、中 `grid[1][k]`、外 `grid[2][k]` が全部同じなら「そろった」です。そろった区画の番号を配列 `out` に集めて返します。何もそろっていなければ空の配列 `[]` が返ります。

データを「リング × 区画」の2次元配列にしておいたおかげで、**同じ区画番号 = 同じ方向** になり、判定がたった1行で書けます。ステップ5で「データは回転が終わってから書きかえる」ようにしたのも、ここで正しい並びを調べるためです。

### 最初からそろっているのを防ぐ

ランダムに並べると、たまたま最初からそろってしまうことがあります。そこで `newBoard()` の最後で、そろっている区画があれば中のリングの玉 `grid[1][k]` だけを別の色に取りかえ、そろいがなくなるまでくり返します。

`guard` は「念のための回数制限」です。ふつうは数回で終わりますが、万が一終わらないとブラウザが固まってしまうので、100回で必ずやめるようにしています。こうした安全装置を入れておくのは良い習慣です。

## finishTurn() のあとでそろいを調べる

`finishTurn()` の最後の行 `busy = false;` を、次の2行に **書きかえます**。

```js:game.js
    chain = 0;
    resolve();
```

回転が終わったら連鎖の数を 0 に戻し、`resolve()`（そろいの処理）を呼びます。`busy` を `false` に戻すのは、`resolve()` で消すものが何もなくなったときにします。

## resolve() … 消して、補充して、もう一度調べる

`finishTurn()` 関数の **下** に追加します。

```js:game.js

  function resolve() {
    const m = findMatches();
    if (!m.length) {
      busy = false;
      return;
    }
    chain++;
    const gain = m.length * 30 * chain + (m.length >= 2 ? 20 * m.length : 0);
    score += gain;
    moves += m.length * 2 + (chain >= 2 ? 1 : 0);
    updateHud();
    $hint.textContent = chain >= 2 ? chain + ' 連鎖！' : 'そろった！手数 +' + (m.length * 2);
    m.forEach(k => { for (let i = 0; i < RINGS; i++) grid[i][k] = rnd(); });
    setTimeout(resolve, 250);
  }
```

### 流れ

1. `findMatches()` でそろった区画を探す。何もなければ `busy = false` にして、次の操作を受けつける
2. そろっていたら `chain` を1増やし、スコアと手数を足す
3. そろった区画の玉を3つとも新しいランダムな色に取りかえる
4. `setTimeout(resolve, 250)` で、0.25 秒後に **もう一度 `resolve()` を呼ぶ**

4 がポイントです。新しく入った玉でまたそろえば、次の `resolve()` でそれも消え、`chain` が 2、3…と増えていきます。そろわなくなるまで自分自身を呼び直すので、連鎖が自然に作れます。

### 点数の計算

- 基本は 1区画につき 30点。それに **連鎖の数をかける** ので、2連鎖目は2倍、3連鎖目は3倍になります
- 一度に2区画以上そろえたら、1区画につき 20点のボーナス
- 手数は1区画につき +2。連鎖（2回目以降）ならさらに +1

「回すと1減る、消すと2増える」ので、うまく消し続ければいつまでも遊べますが、むだに回していると少しずつ減っていく、というバランスになっています。

> [!NOTE]
> `setTimeout(関数, ミリ秒)` は、指定した時間が過ぎたら関数を1回だけ呼びます。`requestAnimationFrame` が「次の画面更新で」なのに対して、こちらは「〇ミリ秒後に」です。

> [!CHECK] 動作チェック
> - スタート直後の盤面では、どの方向も3つの色がそろっていない
> - リングを回して、ある方向の内・中・外が同じ色になると、その3つの玉がパッと別の色に変わる
> - そのとき SCORE が増え（1区画なら 30）、MOVES が 2 増える。ヒントに「そろった！手数 +2」と出る
> - 入れかわった玉でまたそろうと、少ししてそれも消え、ヒントに「2 連鎖！」と出る
