## このステップのゴール

3つのファイルを用意して、画面の土台を作ります。上に「STAGE・SCORE・BEST」と「のこりのダーツ」の表示、まん中にゲームを描く **Canvas**（キャンバス）、その上に重ねるタイトル画面（オーバーレイ）を置きます。

完成すると、こんなゲームになります。

- 画面の上のほうで、木のまとがくるくる回っている
- タップ（または Space）するたびに、下からダーツが1本まっすぐ飛んで、まとに刺さる。刺さったダーツはまとといっしょに回る
- すでに刺さっているダーツに当たったらアウト。まとのふちの星に刺すと +5 点
- 持っているダーツを全部刺すとまとがはじけてステージクリア。ステージが進むと回り方が変わり、5ステージごとにボス

まとやダーツがなめらかに回り続けるゲームなので、**Canvas** に絵を描く方式で作ります。Canvas は「ピクセルの画用紙」で、JavaScript から円や四角を描きこみます。毎フレーム全体を消して描き直すことで、動きを表現します。

- `<script>` は `</body>` の直前に置きます。HTML の要素が全部できたあとで JavaScript が動くので、`getElementById` で確実に要素を取れます。

## game.js

最後に JavaScript です。まずは「Canvas を用意して、毎フレーム描き直す」いちばん小さな形を作ります。

```js:game.js
(() => {
  'use strict';
  const W = 360, H = 600;

  const cv = document.getElementById('cv');
  const ctx = cv.getContext('2d');
  const $ = (id) => document.getElementById(id);
  const scoreEl = $('score'), bestEl = $('best'), stageEl = $('stage-no'), dartsEl = $('darts');
  const overlay = $('overlay'), ovTitle = $('ov-title'), ovText = $('ov-text'), startBtn = $('start'), toast = $('toast');

  const dpr = Math.min(window.devicePixelRatio || 1, 2);
  cv.width = W * dpr; cv.height = H * dpr;
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0);

  // ---- state ----
  let state = 'title'; // title | play | clear | over

  function start() {
    overlay.classList.add('hide');
    state = 'play';
  }

  // ---- update / draw ----
  function update(dt) {
    // ステップ2から、ここで動きを計算する
  }

  function draw() {
    ctx.clearRect(0, 0, W, H);
    ctx.fillStyle = 'rgba(255,255,255,.55)'; ctx.font = '14px system-ui, sans-serif'; ctx.textAlign = 'center';
    ctx.fillText('ここに まと を描いていくよ', W / 2, H / 2);
  }

  let last = performance.now();
  function loop(now) {
    const dt = Math.min(0.033, (now - last) / 1000); last = now;
    update(dt); draw();
    requestAnimationFrame(loop);
  }

  requestAnimationFrame(loop);

  // ---- input ----
  startBtn.addEventListener('click', (e) => { e.stopPropagation(); start(); });
})();
```

### 全体を `(() => { ... })();` で包む

ファイル全体をアロー関数で包んで、その場で呼び出しています（即時実行関数）。こうすると中で作った変数がページ全体に漏れず、ほかのスクリプトと名前がぶつかりません。`'use strict';` は、うっかりミス（宣言していない変数への代入など）をエラーとして教えてくれるモードです。

### 要素の取得

- `cv.getContext('2d')` で、Canvas に絵を描くための道具（コンテキスト）を取り出します。以降の描画はすべて `ctx.〇〇()` で行います。
- `$` は `document.getElementById` を短く書くための小さな関数です。このゲームで使う画面の要素は、ここでまとめて取っておきます（まだ使わないものもあります）。

### 高画質ディスプレイ対応（dpr）

スマホなどの画面は、CSS の 1px を実際には 2〜3 個の点で表示しています（`devicePixelRatio`）。Canvas の解像度が 360×600 のままだと、引きのばされてぼやけてしまいます。

そこで、Canvas の **本当の解像度** を `W * dpr` × `H * dpr` に上げ、`ctx.setTransform(dpr, 0, 0, dpr, 0, 0)` で「描くときは全部 dpr 倍してね」と設定します。こうすると、コードの中では今まで通り 360×600 の座標で描けて、見た目はくっきりになります。重くなりすぎないよう、`Math.min(…, 2)` で最大2倍にしています。

### state … いまどの場面か

`state` は、ゲームがいまどの場面にいるかを表す文字列です。

- `'title'` … タイトル画面
- `'play'` … プレイ中
- `'clear'` … ステージクリアの演出中（ステップ6）
- `'over'` … ゲームオーバー（ステップ5）

「場面ごとにできることを変える」のは、ゲームづくりでよく使う考え方です（**状態遷移**）。

### loop() と dt … ゲームループ

`requestAnimationFrame(loop)` は「次に画面を描きかえるタイミングで `loop` を呼んで」とブラウザに頼む命令です。`loop` の最後でまた自分を予約するので、1秒に約60回 `update()` と `draw()` がくり返されます。これが **ゲームループ** です。

`loop` には、そのときの時刻（ミリ秒）が `now` として渡されます。前回との差を秒に直したものが `dt`（デルタタイム）です。「1秒に何ピクセル動くか」×`dt` で動かせば、60fps の画面でも120fps の画面でも同じ速さになります。タブを切りかえて戻ったときに `dt` が大きくなりすぎてワープしないよう、`Math.min(0.033, …)` で上限をつけています。

- `update(dt)` … 動きや判定を計算する（いまは空っぽ）
- `draw()` … いまの状態を絵にする

この2つを分けておくと、「計算」と「見た目」を別々に考えられて、コードが読みやすくなります。

### スタートボタン

ボタンが押されたら `start()` でオーバーレイを隠し、`state` を `'play'` にします。`e.stopPropagation()` は、このクリックが後ろの画面（ステップ3でタップ＝投げる、にします）まで伝わらないようにする命令です。
