## このステップのゴール

Canvas に **アリーナ**（丸い床・点のもよう・赤い壁）を描き、毎フレーム描き直す **ゲームループ** を動かします。アリーナは画面よりずっと大きいので、「世界のどこを画面のまん中に映すか」を決める **カメラ** も用意します。

## Canvas の大きさを合わせる：resize()

`const boostBtn = ...` の行の下に追加します。

```js:game.js
  let W = 0, H = 0, DPR = 1;
  function resize() {
    const r = stage.getBoundingClientRect();
    DPR = Math.min(window.devicePixelRatio || 1, 2);
    W = Math.max(1, r.width); H = Math.max(1, r.height);
    cv.width = Math.round(W * DPR); cv.height = Math.round(H * DPR);
  }
  window.addEventListener('resize', resize);
  resize();
```

Canvas には **2つの大きさ** があります。

- 見た目の大きさ …… CSS の `width: 100%; height: 100%` で決まる（`#stage` いっぱい）
- 中の解像度 …… `cv.width` / `cv.height` で決まる「何ピクセルの画用紙か」

この2つがずれていると、絵が引きのばされてぼやけます。そこで `getBoundingClientRect()` で `#stage` の見た目の大きさ（`W`・`H`）を調べ、中の解像度をそれに合わせます。

`devicePixelRatio`（`DPR`）は、スマホなどの高精細な画面で「CSS の 1px が実際には何ドットか」を表す数字です。中の解像度を `W * DPR` にしておくと、高精細な画面でもくっきり描けます。大きすぎると重くなるので、`Math.min(..., 2)` で 2 倍までにしています。

## 世界とカメラの変数

`resize();` の下に、世界の見出しとアリーナの半径を追加します。

```js:game.js
  // ---- world ----
  const R = 1300;               // arena radius
```

さらに、`let state = ...` の下に2行追加します。

```js:game.js
  let state = 'title';   // title | play | dying | over
  let lastT = 0;
  let camX = 0, camY = 0, camS = 1;
```

- `R` はアリーナの半径です。中心 (0, 0) から 1300 の円がアリーナで、その外は壁です。これは **世界の座標**（画面のピクセルとは別のものさし）です
- `lastT` は前のフレームの時刻です。ゲームループで「前のフレームから何秒たったか」を計算するのに使います
- `camX, camY` はカメラが見ている世界の位置、`camS` はカメラの倍率（ズーム）です

## 毎フレームの更新：update()

`let camX ...` の下に、見出しと `update()` を追加します。

```js:game.js
  // ---- simulation ----
  function update(dt) {
    const want = Math.min(W, H * 0.8) / 380;
    camS += (want - camS) * Math.min(1, dt * 2);
  }
```

`want` は「ちょうどいい倍率」です。画面の短いほう（縦は 0.8 倍で計算）に、世界の 380 くらいの範囲が映るようにします。スマホでも PC でも、見える範囲がだいたい同じになります。

`camS += (want - camS) * Math.min(1, dt * 2);` は、いまの倍率を目標の倍率へ **少しずつ近づける** 書き方です。差の何割かずつ近づくので、急にズームが変わらず、なめらかに動きます。このあとカメラの位置も同じ書き方で動かします。

`dt` は前のフレームからの経過秒数です。「1秒あたり〇〇」の動きに `dt` をかけると、画面のなめらかさ（1秒に60回か120回か）にかかわらず同じ速さで動きます。

## アリーナを描く：draw()

`update()` の下に追加します。

```js:game.js
  // ---- drawing ----
  function draw(t) {
    ctx.setTransform(DPR, 0, 0, DPR, 0, 0);
    ctx.fillStyle = '#1a1d3a';
    ctx.fillRect(0, 0, W, H);
    ctx.save();
    ctx.translate(W / 2, H / 2);
    ctx.scale(camS, camS);
    ctx.translate(-camX, -camY);
    const vw = W / 2 / camS + 40, vh = H / 2 / camS + 40;
    const x0 = camX - vw, x1 = camX + vw, y0 = camY - vh, y1 = camY + vh;

    // arena floor
    ctx.beginPath(); ctx.arc(0, 0, R, 0, Math.PI * 2);
    ctx.fillStyle = '#20244a'; ctx.fill();
    // hex dot grid
    ctx.save(); ctx.clip();
    ctx.fillStyle = 'rgba(140, 150, 230, .16)';
    const g = 46;
    for (let y = Math.floor(y0 / g) * g; y < y1; y += g) {
      const off = (Math.round(y / g) & 1) ? g / 2 : 0;
      for (let x = Math.floor(x0 / g) * g + off; x < x1; x += g) { ctx.fillRect(x - 2, y - 2, 4, 4); }
    }
    ctx.restore();
    // wall
    ctx.lineWidth = 14; ctx.strokeStyle = 'rgba(255, 80, 90, .75)';
    ctx.beginPath(); ctx.arc(0, 0, R + 7, 0, Math.PI * 2); ctx.stroke();
    ctx.restore();
  }
```

### カメラで世界を映す

```js:game.js
    ctx.translate(W / 2, H / 2);
    ctx.scale(camS, camS);
    ctx.translate(-camX, -camY);
```

この3行がカメラです。下の行から読むと分かりやすくなります。

1. `translate(-camX, -camY)` …… カメラが見ている点を原点 (0, 0) に持ってくる
1. `scale(camS, camS)` …… 原点を中心に `camS` 倍に拡大する
1. `translate(W / 2, H / 2)` …… 原点を画面のまん中に動かす

これで、このあとは **世界の座標のまま** `ctx.arc(0, 0, R, ...)` のように描くだけで、カメラに合わせて画面に映ります。最初の `ctx.setTransform(DPR, 0, 0, DPR, 0, 0)` は、変形を一度リセットして DPR 倍にする命令です。これで以降は CSS のピクセルで考えて描けます。`ctx.save()` と `ctx.restore()` で、カメラの変形を描き終わったら元に戻します。

### 見えている範囲だけ描く

`x0, x1, y0, y1` は、いま画面に映っている世界の範囲です（`W / 2 / camS` が画面の半分の幅を世界の長さに直したもの。少し余白 40 をつけています）。アリーナは広いので、点のもようは **この範囲の中だけ** 描きます。全部描くと何万個にもなって重くなるからです。

### 床・点のもよう・壁

- 床は半径 `R` の円をぬりつぶします
- `ctx.clip()` は「いま作った円の中だけに描く」という切り抜きです。点のもようが壁の外にはみ出しません。切り抜きは `save()`〜`restore()` の間だけ有効です
- 点は 46 ごとに置き、1行おきに半分ずらして（`off`）、ハチの巣のような並びにしています
- 最後に、半径 `R + 7` の太い赤い線で壁を描きます

## ゲームループ：frame()

ファイルの最後の `})();` の **上** に追加します。

```js:game.js
  // ---- loop ----
  function frame(t) {
    const dt = Math.min(0.05, (t - (lastT || t)) / 1000);
    lastT = t;
    if (W !== stage.clientWidth || H !== stage.clientHeight) resize();
    update(dt);
    draw(t);
    requestAnimationFrame(frame);
  }
  requestAnimationFrame(frame);
```

`requestAnimationFrame(frame)` は「次に画面を描きかえるタイミングで `frame` を呼んで」とブラウザに頼む命令です。`frame()` の最後でもう一度頼むので、1秒に約60回（画面によっては120回）、`update()` と `draw()` がくり返されます。これが **ゲームループ** です。

- `frame` には、ページを開いてからのミリ秒 `t` が渡されます。前回との差を 1000 で割って秒にしたものが `dt` です
- `Math.min(0.05, ...)` で `dt` を最大 0.05 秒に抑えます。タブを切りかえて戻ったときなどに `dt` が大きくなりすぎ、ヘビが壁の向こうへワープするのを防ぎます
- `#stage` の大きさが変わっていたら（スマホを横にした、など）`resize()` し直します

> [!CHECK] 動作チェック
> - タイトル画面の後ろに、紺色の床と、ハチの巣状にならんだうすい点のもようが見える
> - スタートを押すと、点のもようがはっきり見える（まだ何も動かない）
> - PC でウィンドウの大きさを変えても、絵が引きのばされたりぼやけたりしない
> - 試しに `let camX = 0, camY = 1200` に変えて再読み込みすると、画面の下のほうに赤い壁のカーブが見える（確認したら `camY = 0` に戻す）
