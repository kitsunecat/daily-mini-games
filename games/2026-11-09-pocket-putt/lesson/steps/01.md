## このステップのゴール

3つのファイルを用意して、ゲーム画面の土台を作ります。上に「HOLE・残り打数・SCORE・BEST」の表示、まん中にゲームを描く **Canvas**（キャンバス）、その上に重ねるタイトル画面（オーバーレイ）とメッセージ（トースト）、下に「PAR・今の打数」の表示を置き、Canvas に **木の外枠と芝生のコース** を描くところまで進めます。

完成すると、こんなゲームになります。

- 上から見たミニゴルフのコース。下のティーにボールがあり、上のほうに旗の立ったカップがある
- ボールを **引っぱって離す** と、引っぱった向きと **反対** へ転がる。引っぱるほど強く打てる
- ボールは外枠や木の壁で **跳ね返る**。バンクショット（壁に当てて曲げる）でカップを狙う
- 打つたびに **残り打数** が1減り、カップインすると **パー − 1** 打もどる（ホールインワンはさらに +2）。パーで入れれば1打ずつ減り、バーディーなら減らない
- ホールが進むと **砂**（止まりやすい）、**池**（1打罰で打った場所へもどる）、**左右に動く壁** が出てくる
- 残り打数が 0 になったらゲームオーバー。スコアのベストは保存される

## game.js

最後に JavaScript です。全体を `(() => { ... })();` で囲んでいます。これは **即時実行関数** といって、中で作った変数がページ全体に漏れ出さないようにする書き方です。

```js:game.js
(() => {
  'use strict';
  const W = 360, H = 600;           // 論理サイズ
  const M = 16;                     // コースの外枠
  const BALL_R = 7, CUP_R = 11;
  const MAX_SPEED = 950, MAX_PULL = 150;
  const START_BALLS = 10;
  const BEST_KEY = 'pocket-putt-best';

  const cv = document.getElementById('cv');
  const ctx = cv.getContext('2d');
  const $ = id => document.getElementById(id);
  const ui = {
    hole: $('hole'), balls: $('balls'), score: $('score'), best: $('best'),
    par: $('par'), strokes: $('strokes'), overlay: $('overlay'),
    title: $('ov-title'), text: $('ov-text'), start: $('start'), toast: $('toast'),
  };

  // ---------- 状態 ----------
  let state = 'title';   // title | aim | roll | sink | over
  let course = null;
  let time = 0;

  function newGame() {
    ui.overlay.classList.add('hide');
    state = 'aim';
  }

  // ---------- 物理 ----------
  function step(dt) {
    time += dt;
  }

  // ---------- 描画 ----------
  function rrect(x, y, w, h, r) {
    ctx.beginPath(); ctx.moveTo(x + r, y); ctx.arcTo(x + w, y, x + w, y + h, r); ctx.arcTo(x + w, y + h, x, y + h, r);
    ctx.arcTo(x, y + h, x, y, r); ctx.arcTo(x, y, x + w, y, r); ctx.closePath();
  }

  function draw() {
    ctx.clearRect(0, 0, W, H);
    // 外枠（木）
    ctx.fillStyle = '#7a4b25'; rrect(0, 0, W, H, 14); ctx.fill();
    ctx.fillStyle = '#a5683a'; rrect(4, 4, W - 8, H - 8, 11); ctx.fill();
    // 芝
    ctx.save(); rrect(M, M, W - 2 * M, H - 2 * M, 6); ctx.clip();
    for (let i = 0; i < 14; i++) {
      ctx.fillStyle = i % 2 ? '#3a9a50' : '#349148';
      ctx.fillRect(M, M + i * (H - 2 * M) / 14, W - 2 * M, (H - 2 * M) / 14 + 1);
    }
    ctx.restore();
  }

  // ---------- 入力 ----------
  ui.start.addEventListener('click', newGame);
  ui.overlay.addEventListener('pointerdown', e => { if (e.target === ui.overlay) newGame(); });

  // ---------- サイズ ----------
  function resize() {
    const stage = $('stage');
    const aw = stage.clientWidth - 16, ah = stage.clientHeight - 8;
    const s = Math.max(0.3, Math.min(aw / W, ah / H));
    const dpr = Math.min(window.devicePixelRatio || 1, 3);
    cv.style.width = Math.floor(W * s) + 'px'; cv.style.height = Math.floor(H * s) + 'px';
    cv.width = Math.round(W * s * dpr); cv.height = Math.round(H * s * dpr);
    ctx.setTransform(s * dpr, 0, 0, s * dpr, 0, 0);
  }
  window.addEventListener('resize', resize);
  resize();

  let last = performance.now();
  function loop(now) {
    const dt = Math.min(0.033, (now - last) / 1000); last = now;
    step(dt); draw();
    requestAnimationFrame(loop);
  }
  requestAnimationFrame(loop);
})();
```

### 仮想の画面サイズと定数

このゲームは、**幅 360 × 高さ 600 の仮想の画面** に描くと決めて作ります。実際の画面の大きさは機種によってバラバラですが、あとで `resize()` がまとめて拡大・縮小してくれるので、描くときは「360 × 600」のつもりで座標を書けば OK です。

- `M = 16` … 外枠（木のふち）の太さ。芝生は `M` 〜 `W - M` の内側です
- `BALL_R`・`CUP_R` … ボールとカップの半径
- `MAX_SPEED`・`MAX_PULL` … いちばん強く打ったときの速さと、そのために必要な引っぱりの長さ（ステップ3）
- `START_BALLS` … 最初の残り打数、`BEST_KEY` … ハイスコアを保存するときの名前（ステップ8）

今はまだ使わない定数もありますが、最初にまとめて書いておくと全体の設計が見わたせます。`ui` には、よく書きかえる HTML の要素をまとめて入れておきます。

### resize() … 仮想の画面を実際の大きさに合わせる

`resize()` は、`#stage` の大きさを読み取り、仮想の画面（`W` × `H`）がまるごと入る倍率 `s` を求めます。横に合わせた倍率と縦に合わせた倍率の **小さいほう** を使うのがコツで、こうすると縦長の画面でも横長の画面でもはみ出しません。

スマホの画面は、CSS の 1px を実際には 2〜3 個の点（物理ピクセル）で表示しています。この倍率が `devicePixelRatio`（`dpr`）です。`cv.style.width` には見た目の大きさを、`cv.width` には **その dpr 倍** の内部解像度を入れておくと、くっきり表示されます。

最後の `ctx.setTransform(s * dpr, 0, 0, s * dpr, 0, 0)` で、「これから描く座標を全部この倍率で拡大してね」と Canvas に伝えます。これで `draw()` の中は仮想の座標のまま書けます。

### draw() … コースを描く

`draw()` は、毎回 `clearRect` で画面を消してから全部を描き直します。

- `rrect()` は **角の丸い四角形** のパスを作る小さな関数です。`arcTo` で4つの角を丸めながら一周します。パスを作ったあと `ctx.fill()` で塗りつぶします
- **外枠（木）** … こげ茶の角丸四角の上に、ひとまわり小さい明るい茶色を重ねて、木のふちらしく見せます
- **芝** … 横長の帯を14本、色を交互に変えて並べると、刈りそろえた芝生のしま模様になります。帯の高さに `+ 1` しているのは、小数の座標で帯と帯のあいだにすき間が見えないようにするためです

`ctx.save()` → `ctx.clip()` → `ctx.restore()` は **クリッピング** です。`clip()` すると、直前に作ったパス（ここでは芝生の角丸四角）の **内側にしか描けなくなります**。しま模様の四隅がはみ出さないのはこのおかげです。あとで描く池や砂、ボールも、この内側に描きます。`restore()` で「内側にしか描けない」設定を元にもどします。

### ゲームループと dt

`requestAnimationFrame(loop)` は「次に画面を描きかえるタイミングで `loop` を呼んで」とブラウザにお願いする関数です。`loop` の最後でまた自分を予約するので、1秒に約60回くり返し呼ばれ続けます。これを **ゲームループ** と呼びます。

`loop` には、ブラウザが今の時刻（ミリ秒）を渡してくれます。前回との差を秒になおしたものが `dt`（デルタタイム）です。動きを「1秒あたり何ピクセル × dt」で計算すれば、画面の更新が速い機種でも遅い機種でも同じ速さで動きます。`Math.min(0.033, ...)` は、タブを切りかえて戻ってきたときなどに dt が大きくなりすぎてボールがワープしないようにする上限です。

ループでは、`step(dt)`（状態を進める）と `draw()`（描く）を交互に呼びます。今の `step()` は経過時間 `time` を数えるだけですが、ここに物理を少しずつ足していきます。

`state` はゲームの状態を表す文字列です。`'title'`（タイトル画面）、`'aim'`（狙っている）、あとで `'roll'`（転がっている）、`'sink'`（カップに吸いこまれ中）、`'over'`（ゲームオーバー）も使います。スタートボタンを押すか、オーバーレイの余白をタップすると `newGame()` が呼ばれ、オーバーレイが消えます。

> - スタートを押すとタイトル画面が消え、木の外枠に囲まれたしま模様の芝生のコースが見える
