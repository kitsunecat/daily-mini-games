## このステップのゴール

**ゲームループ** を作って、画面を毎フレーム描き直します。走った距離に合わせて道路のしま模様が手前へ流れ、スコアが増えていく「走っている感じ」を出します。

## ゲームの状態を表す変数

`const overlay = ...` の **上** に、スコアの表示先を足します。

```js:game.js
  const scoreEl = document.getElementById('score');
```

`let W = 0, H = 0, dpr = 1;` の下を次のようにします（`skyline` はステップ2のまま）。

```js:game.js
  let state = 'title';
  let player, dist, speed, lastTime;
  let skyline = [];
```

- `state` はゲームの場面です。`'title'`（タイトル画面）と `'play'`（プレイ中）から始め、あとで `'crash'`（ぶつかった直後）と `'over'`（ゲームオーバー）を足します。場面ごとに「何を受け付けて、何を動かすか」を `state` で切り替えるのがゲーム作りの基本パターンです。
- `player` はプレイヤーの情報をまとめたオブジェクト、`dist` は走った距離、`speed` は1秒あたりに進む距離です。
- `lastTime` は前のフレームの時刻です（理由は後で説明します）。

## 開始とリセット、スコア表示

`// ---------- 描画 ----------` の **上** に、次のブロックを追加します。

```js:game.js
  // ---------- ゲーム開始 ----------
  function reset() {
    player = { lane: 0, x: 0, y: 0, vy: 0, slide: 0, run: 0 };
    dist = 0;
    speed = 13;
    updateHud();
  }

  function start() {
    reset();
    state = 'play';
    overlay.classList.add('hidden');
    lastTime = performance.now();
  }

  const calcScore = () => Math.floor(dist);
  function updateHud() {
    scoreEl.textContent = calcScore();
  }

  startBtn.addEventListener('click', (e) => { e.stopPropagation(); start(); });

  // ---------- 更新 ----------
  function update(dt) {
    if (state !== 'play') return;

    speed = Math.min(34, 13 + dist / 90);
    const dz = speed * dt;
    dist += dz;
    player.run += dz;

    updateHud();
  }
```

そして、ファイル末尾にあったステップ1の

```js:game.js
  startBtn.addEventListener('click', () => { overlay.classList.add('hidden'); });
```

は **削除** してください（上で `start()` を呼ぶものに置き換えました）。

- `player` の中身は、今は `run`（走った距離。足の動きやしま模様に使う）だけを使います。`lane`・`x`・`y`・`vy`・`slide` は次のステップから使うので、先に 0 で用意しておきます。
- `reset()` は「最初からやり直すための初期化」、`start()` は「プレイを始める」処理です。リトライのときも同じ `start()` を呼べば済むように分けておきます。
- `speed = Math.min(34, 13 + dist / 90)` で、距離 90 進むごとに速さが 1 ずつ上がり、最大 34 で頭打ちになります。走るほど難しくなる仕組みはこの1行だけです。
- HUD（ヘッドアップディスプレイ）は画面上部のスコア表示のことです。今のスコアは距離をそのまま整数にしたもの（`Math.floor` で切り捨て）です。

## 流れるしま模様（枕木）

`draw()` の中、道路の台形を塗った `ctx.fill();` の **下**、`// レーン線` の **上** に追加します。

```js:game.js
    // 枕木（流れるしま模様）
    const off = (player ? player.run : 0) % 4;
    for (let z = -off; z < 120; z += 4) {
      if (z < -6) continue;
      const a = proj(-LANE_GAP * 1.55, 0, z), b = proj(LANE_GAP * 1.55, 0, z);
      const c = proj(LANE_GAP * 1.55, 0, z + 1.2);
      ctx.fillStyle = 'rgba(255,255,255,0.06)';
      ctx.fillRect(a.x, c.y, b.x - a.x, a.y - c.y);
    }
```

4 単位おきに、奥行き 1.2 の薄い帯を道路に描きます。カメラは動かさず、**帯の位置を走った距離ぶんだけ手前にずらす** ことで前に進んでいるように見せています。`% 4`（4で割った余り）を使うと、ずらし量が 0〜4 の範囲でくり返すので、帯を無限に用意しなくても永遠に流れ続けます。

## ゲームループ

ファイル末尾の

```js:game.js
  resize();
  draw();
```

を、次のように **置き換えます**。

```js:game.js
  function loop(now) {
    const dt = Math.min(0.05, (now - (lastTime || now)) / 1000);
    lastTime = now;
    update(dt);
    draw();
    requestAnimationFrame(loop);
  }

  resize();
  reset();
  requestAnimationFrame(loop);
```

### requestAnimationFrame とは

`requestAnimationFrame(関数)` は「次に画面を書き換えるタイミングでこの関数を呼んで」とブラウザに頼む命令です。`loop` の最後で自分自身をもう一度頼むことで、1秒間に約60回（画面のリフレッシュレートに合わせて）`update` → `draw` がくり返されます。これがゲームループです。

### dt（デルタタイム）を使う理由

`loop` には呼ばれた時刻 `now`（ミリ秒）が渡されます。前回との差を秒に直したものが `dt` です。「1フレームで 0.2 進む」ではなく「**1秒で speed 進む × 経過秒数**」と書くことで、60Hz の画面でも 120Hz の画面でも同じ速さでゲームが進みます。

`Math.min(0.05, ...)` は、タブを裏に回して戻ったときなどに `dt` が巨大になり、一瞬でワープしてしまうのを防ぐ上限です。`start()` で `lastTime = performance.now()` としているのも、タイトル画面にいた時間を `dt` に含めないためです。

> [!CHECK] 動作チェック
> - スタートを押すと、道路の上の薄いしま模様が手前に向かって流れ始める
> - 右上の SCORE が増えていき、しばらく待つとしま模様の流れが速くなる
> - スタート前（タイトル画面）では SCORE は 0 のまま
