## このステップのゴール

3つのファイルを用意して、ゲーム画面の土台を作ります。上に「STAGE・SCORE・BEST」の表示、まん中にゲームを描く **Canvas**（キャンバス）、その上に重ねるタイトル画面（オーバーレイ）、下にボールの数の表示を置き、Canvas に盤面のマス目・危険ライン・床を描くところまで進めます。

完成すると、こんなゲームになります。

- 横7列の盤面の上から、**数字のついたブロック** が1列ずつ下りてくる
- 画面をドラッグしてねらいを決め、指（マウス）を離すと、持っているボールを **一斉に発射**
- ボールは壁や天井、ブロックで跳ね返る。ブロックの数字は「あと何回当てれば壊れるか」
- **緑のリング** に触れると、次のターンからボールが1個増える
- ボールが全部床に戻ったらターン終了。ブロックが1段下がり、**一番下の列** まで来たらゲームオーバー

- `<canvas id="cv">` が、ゲームを描く画用紙です。大きさはあとで JavaScript から決めます。

- `#overlay` はタイトル画面とゲームオーバー画面をかねるパネルです。操作説明にあるキーボード操作はステップ8で作ります。
- `<script>` は `</body>` の直前に置きます。HTML の要素が全部できたあとで JavaScript が動くので、`getElementById` で確実に要素を取れます。

## game.js

最後に JavaScript です。全体を `(() => { ... })();` で囲んでいます。これは **即時実行関数** といって、中で作った変数がページ全体に漏れ出さないようにする書き方です。

```js:game.js
(() => {
  'use strict';
  const COLS = 7, ROWS = 8, TOP = 0.6, BW = COLS, BH = TOP + ROWS + 1.0;
  const FLOOR = BH - 0.25;

  const cv = document.getElementById('cv');
  const ctx = cv.getContext('2d');
  const stageEl = document.getElementById('stage');
  const $ = id => document.getElementById(id);
  const overlay = $('overlay'), ovTitle = $('ov-title'), ovText = $('ov-text'), startBtn = $('start');

  let scale = 40, dpr = 1;
  let state = 'title'; // title | aim | fire | over
  let bricks = null;

  function resize() {
    const r = stageEl.getBoundingClientRect();
    const aw = r.width - 16, ah = r.height - 8;
    scale = Math.max(10, Math.min(aw / BW, ah / BH));
    dpr = Math.min(window.devicePixelRatio || 1, 2);
    cv.style.width = (BW * scale) + 'px';
    cv.style.height = (BH * scale) + 'px';
    cv.width = Math.round(BW * scale * dpr);
    cv.height = Math.round(BH * scale * dpr);
  }
  window.addEventListener('resize', resize);
  resize();

  // ---- game logic ----
  function startGame() {
    bricks = [];
    state = 'aim';
    overlay.classList.add('hide');
  }

  // ---- render ----
  function draw(time) {
    const s = scale * dpr;
    ctx.setTransform(1, 0, 0, 1, 0, 0);
    ctx.fillStyle = '#140e28';
    ctx.fillRect(0, 0, cv.width, cv.height);
    ctx.setTransform(s, 0, 0, s, 0, 0);

    // grid dots
    ctx.fillStyle = 'rgba(255,255,255,.05)';
    for (let c = 1; c < COLS; c++) for (let r = 0; r <= ROWS; r++) ctx.fillRect(c - 0.02, TOP + r - 0.02, 0.04, 0.04);
    // danger line
    ctx.strokeStyle = 'rgba(255,90,120,.25)';
    ctx.lineWidth = 0.04; ctx.setLineDash([0.15, 0.12]);
    ctx.beginPath(); ctx.moveTo(0, TOP + ROWS - 1); ctx.lineTo(BW, TOP + ROWS - 1); ctx.stroke();
    ctx.setLineDash([]);
    // floor
    ctx.fillStyle = 'rgba(185,166,255,.25)';
    ctx.fillRect(0, FLOOR, BW, 0.04);

    if (!bricks) return;
  }

  function loop(t) {
    draw(t);
    requestAnimationFrame(loop);
  }
  requestAnimationFrame(loop);

  // ---- input ----
  startBtn.addEventListener('click', e => { e.stopPropagation(); startGame(); });
})();
```

### 盤面の単位で考える

このゲームでは、座標を **ピクセルではなく「マス」** で考えます。ブロック1個ぶんの幅が `1` です。

- `COLS = 7` … 横のマス数。盤面の幅 `BW` も 7 になります
- `ROWS = 8` … ブロックが並べる縦のマス数
- `TOP = 0.6` … 天井からブロックの1段目までのすき間
- `BH = TOP + ROWS + 1.0` … 盤面の高さ。ブロック8段の下に、ボールを撃つためのスペースを 1 マスぶん足しています
- `FLOOR = BH - 0.25` … 床の位置。ボールはここから撃ち出され、ここに戻ってきます

マス単位にしておくと「ブロックは横 `c` 列目、縦 `r` 段目」とそのまま書けて、スマホでも PC でも同じ計算で済みます。

### resize() … マスをピクセルに変換する倍率を決める

`resize()` は、`#stage` の大きさを読み取り、盤面（`BW` × `BH` マス）がまるごと入る最大の **1マスあたりのピクセル数** `scale` を求めます。横に合わせた倍率と縦に合わせた倍率の小さいほうを使うのがコツで、こうすると縦長の画面でも横長の画面でも盤面がはみ出しません。

スマホの画面は、CSS の 1px を実際には 2〜3 個の点（物理ピクセル）で表示しています。この倍率が `devicePixelRatio`（`dpr`）です。`cv.style.width` には見た目の大きさを、`cv.width` には **その dpr 倍** の内部解像度を入れておくと、くっきり表示されます。重くなりすぎないよう、dpr は最大 2 にしています。

### draw() … マス単位で描く

`draw()` の最初で、いったん変換をリセット（`setTransform(1, 0, 0, 1, 0, 0)`）して画面全体を背景色で塗り、そのあと `ctx.setTransform(s, 0, 0, s, 0, 0)` で **全体を `scale × dpr` 倍に拡大** します。これ以降は `ctx.fillRect(0, FLOOR, BW, 0.04)` のように、マスの単位のまま描けます（幅 `0.04` マスの細い線、という意味です）。

- **grid dots** … マスの角に小さな点を打って、盤面のマス目をうっすら見せています
- **danger line** … 下から2段目の上に引く赤い点線。ブロックがこの線を越えた段（一番下の列）まで来るとゲームオーバーになります。`setLineDash([0.15, 0.12])` で「線 0.15・すき間 0.12」の点線になります
- **floor** … ボールが戻ってくる床の線

`if (!bricks) return;` は「まだゲームが始まっていないなら、ここから先（ブロックやボール）は描かない」という意味です。次のステップから、この下に描くものを足していきます。

### ゲームループ

`requestAnimationFrame(loop)` は「次に画面を描きかえるタイミングで `loop` を呼んで」とブラウザにお願いする関数です。`loop` の最後でまた自分を予約するので、1秒に約60回くり返し呼ばれ続けます。これを **ゲームループ** と呼びます。`loop` に渡される `t` はミリ秒単位の時刻で、あとで点滅などのアニメーションに使います。

> [!NOTE]
> このゲームは、1フレームごとに決まった量だけ動かす作り方をしています（ボールは「1フレームで 0.24 マス」など）。ターン制でタイミングの正確さがそれほど要らないので、計算をシンプルにできます。

`state` はゲームの状態を表す文字列です。`'title'`（タイトル画面）、`'aim'`（ねらい中）、`'fire'`（ボールが飛んでいる）、`'over'`（ゲームオーバー）の4つを使います。スタートボタンを押すと `startGame()` が呼ばれ、`'aim'` になってオーバーレイが消えます。

> [!CHECK] 動作チェック
> - タイトル画面に「ボールバースト」とスタートボタンが出る
> - スタートを押すとタイトル画面が消え、濃い紫の縦長の盤面に、うっすらしたマス目の点・赤い点線・下の床の線が見える
> - ブラウザの幅や高さを変えても、盤面の比率は変わらずに中央に収まる
> - 開発者ツールの Console にエラーが出ていない
