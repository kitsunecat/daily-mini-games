## このステップのゴール

今は「となり同士が同じ絵柄」という仮の配り方なので、簡単すぎます。かといって、絵柄を完全にランダムに配ると、**どうやっても最後まで消せない山** ができてしまうことがあります（たとえば、同じ絵柄の2枚が上下にぴったり重なっていると、上の牌を取るには下の牌が必要になり、絶対に取れません）。

そこで、**実際に牌を取っていく手順を先にシミュレーションして**、取った順にペアの絵柄を決める、という方法で「必ず解ける山」を作ります。あわせて、取れるペアが1組も無くなった **手づまり** を見つけられるようにします。

## 配列を混ぜる関数と、絵柄の配り方

`isFree()` の **下** に追加します。

```js:game.js
  const shuffleArr = (a) => { for (let i = a.length - 1; i > 0; i--) { const j = Math.floor(Math.random() * (i + 1)); [a[i], a[j]] = [a[j], a[i]]; } return a; };

  // assign kinds so that a full solution exists (simulate removal)
  function assignKinds(list, kindCount) {
    for (let attempt = 0; attempt < 300; attempt++) {
      const rem = list.slice(), pairs = [];
      let ok = true;
      while (rem.length) {
        const free = rem.filter((t) => isFree(t, rem));
        if (free.length < 2) { ok = false; break; }
        shuffleArr(free);
        const a = free[0], b = free[1];
        pairs.push([a, b]);
        rem.splice(rem.indexOf(a), 1); rem.splice(rem.indexOf(b), 1);
      }
      if (!ok) continue;
      const kinds = shuffleArr([...Array(36).keys()]).slice(0, kindCount);
      pairs.forEach((p, i) => { const k = kinds[i % kinds.length]; p[0].kind = k; p[1].kind = k; });
      return true;
    }
    return false;
  }
```

### shuffleArr() … 配列をランダムに混ぜる

**フィッシャー–イェーツのシャッフル** と呼ばれる有名な方法です。配列の後ろから順に、「自分より前（自分をふくむ）のランダムな位置」と入れかえていきます。どの並び方も同じ確率で出てくる、かたよりのない混ぜ方です。`[a[i], a[j]] = [a[j], a[i]]` は、2つの値を入れかえる書き方（分割代入）です。

### assignKinds() … 必ず解けるように絵柄を配る

1. 牌の一覧をコピーして `rem`（残りの牌）にします。`slice()` は配列のコピーを作ります。本物の `tiles` は減らしません
2. `rem` の中で **取れる牌** を `isFree(t, rem)` で集めます。ステップ4で `isFree` に一覧を渡せるようにしたのは、このためです
3. 取れる牌をシャッフルして、先頭の2枚を「ペア」として `pairs` に記録し、`rem` から取りのぞきます
4. これを `rem` が空になるまでくり返します。途中で取れる牌が2枚未満になったら、この取り方は失敗なので、最初からやりなおします（最大 300 回）
5. 最後まで取りきれたら、記録したペアに **同じ絵柄** を割りあてます。0〜35 をシャッフルして `kindCount` 種類だけ選び、`kinds[i % kinds.length]` で順に使います。ペアの数のほうが多いときは、同じ絵柄が2ペア以上になります

こうして配った山は、少なくとも「シミュレーションと同じ順番で取れば全部消せる」ことが保証されます。ただし、プレイヤーがちがう順番で取ると、途中で手づまりになることもあります。そこがこのゲームの考えどころです。

## buildStage() で使う

`buildStage()` の中の、仮の絵柄の行を **書きかえ** ます。

```js:game.js
    tiles = list.map((p) => ({ ...p, kind: 0, el: null, alive: true }));
    assignKinds(tiles, Math.min(36, 12 + stage * 6));
```

絵柄の種類は、ステージ1で 18 種類、ステージ2で 24 種類……と 6 種類ずつ増え、36 種類で止まります。種類が多いほど同じ絵柄が少なくなり、ペアを探すのがむずかしくなります。

## 取れるペアを数える

`const alive = ...` の行の **下** に追加します。

```js:game.js
  function freePairs() {
    const al = alive(), free = al.filter((t) => isFree(t, al)), res = [];
    for (let i = 0; i < free.length; i++) for (let j = i + 1; j < free.length; j++) if (free[i].kind === free[j].kind) res.push([free[i], free[j]]);
    return res;
  }
```

取れる牌を全部集めて、その中から **同じ絵柄の2枚の組** をすべて探します。`j` を `i + 1` から始めると、同じ組を2回数えたり、自分自身と組にしたりしません。

## 手づまりを知らせる

`tap()` の最後と、そのすぐ下を次のように変えます（`checkStuck();` の呼び出しと、`checkStuck()` 関数を追加）。

```js:game.js
    if (alive().length === 0) { running = false; setMsg('ぜんぶ消せた！'); return; }
    checkStuck();
  }

  function checkStuck() {
    if (freePairs().length) { setMsg('同じ絵柄をペアで消そう'); return; }
    setMsg('手づまり…');
  }
```

`startStage()` の最後にも `checkStuck();` を足します。

```js:game.js
  function startStage() {
    $('overlay').classList.add('hide');
    buildStage();
    running = true;
    setMsg('同じ絵柄をペアで消そう');
    checkStuck();
  }
```

ペアを消すたびに、取れるペアが残っているかを調べます。1組も無ければメッセージで知らせます。次のステップで、ここから「シャッフル」で立てなおせるようにします。

> [!CHECK] 動作チェック
> - 再読み込みするたびに、絵柄の配り方が変わる。となり同士が同じ絵柄、ということは無くなった
> - 明るい牌の中から同じ絵柄を探して、どんどん消していける
> - わざと考えずに取っていくと、「手づまり…」と出ることがある（出ないこともあります）
> - うまく取りきると「ぜんぶ消せた！」と出る
